\section{Introduction}

This chapter specifies the two detectors compared in this report and fixes the rules by which they
are scored. Choosing an evaluation protocol after seeing comparative results risks introducing bias,
so the protocol was fixed before the benchmark result was examined.

The chapter is organised around the fairness problem of Section~\ref{sec:problem}. Each asymmetry
listed there is addressed by a specific choice recorded here: the network's receptive field is
matched to the CFAR window; both detectors are reduced to the same output type and scored by one
code path; operating points are matched at measured rather than design false-alarm rate; and results
are reported at more than one matching tolerance.

\subsection*{What is held in common, and what is not}
\label{sec:whatiscommon}

Both arms turn the same range--Doppler map into a per-cell score map, and both score maps are then
handled identically. What they share is the \textbf{same underlying data} --- the identical frames
from the identical processing chain of Chapter~\ref{chp:simulator}; a \textbf{comparable local
spatial footprint} of $\CfarWinR \times \CfarWinD$ cells, by construction; and the \textbf{same
downstream evaluation} --- one peak extractor, one matcher, one set of metrics, one code path.

What they do \emph{not} share is the transform applied between the map and the score. CFAR operates
on range--Doppler power and forms a local ratio statistic; TinyCNN applies a fixed logarithmic
normalisation relative to the frame median (Section~\ref{sec:inputrep}). \textbf{Their input
processing is therefore not mathematically identical}, and this report does not claim it is. Each arm
has a fixed, detector-specific transform that is part of what that detector \emph{is}: a CFAR
detector without its ratio is not CFAR, and a network evaluated on a different normalisation from the
one it was trained on is not the trained network. The controlled variable is the local decision rule,
with as many other factors held common as is practical.

\section{The classical arm}

\subsection{Window geometry}

The reference window used throughout this report spans \CfarWinR{} bins in range by \CfarWinD{} in
Doppler. Of its \CfarWinCells{} cells, \textbf{1} is the cell under test, \textbf{\CfarNGuard{}} are
guard cells excluded from the estimate, and \textbf{\CfarNRef{}} are reference cells forming the
background estimate $Z$ (Figure~\ref{fig:window}).

\begin{figure}[htbp]
\centering
\includegraphics[width=0.95\textwidth]{figures/Chapter4/ch4_fig1_window.png}
\caption[The CFAR reference window used]{The reference window used by every CFAR arm in this report.
Counting outward from the centre, the range axis has \CfarGuardR{} guard cells then \CfarTrainR{}
reference cells on each side; the Doppler axis has \CfarGuardD{} and \CfarTrainD{}.}
\label{fig:window}
\end{figure}

Two aspects of that geometry were decided by measurement rather than convention.

\textbf{The guard count follows the measured point spread function.} Chapter~\ref{chp:simulator}
measured a mainlobe spanning about two bins. The guard ring must cover a target's own spread, or the
target inflates its own threshold and suppresses itself, so \CfarGuardR{} guard cells per side is the
smallest value that does the job.

\textbf{The window is rectangular because the two axes are not alike.} The range axis has
\RadarRangeBins{} bins and no large-scale structure; the Doppler axis has only \RadarM{} and carries
the zero-Doppler clutter ridge. A window sized for range would span a third of the Doppler axis and
drag ridge energy across a wide band of thresholds.

Candidate geometries were compared on \texttt{bench2\_tune}, a split used for nothing else, and
$\CfarWinR \times \CfarWinD$ was selected there before any read of the test split
(Figure~\ref{fig:geomsweep}, Appendix~\ref{app:tables}). The separation matters: the network's
operating point is selected on \texttt{bench2\_val}, so using one split for both selections would
tune one arm on the other's selection set. What this geometry establishes for the comparison is that
both detectors observe the same local extent of the map. One qualification is recorded rather than
repaired: \textbf{SO-CFAR did not take part in the selection}, having been added to the project after
the geometry was chosen, so it inherits a window selected on the evidence of the other three
variants. If SO is disadvantaged by that, the disadvantage is a property of this evaluation and not
of the algorithm.

\subsection{Variants}

Four variants are evaluated, differing only in how the reference cells become $Z$: CA, GO, SO and OS,
as described in Section~\ref{sec:cfar_failures}. OS uses a rank fraction of \CfarOsRank{}, which was
never swept --- a stated limitation, since a better-tuned OS might do better than the one reported
here.

\subsection{Threshold calibration}
\label{sec:alphacal}

Two distinct calibrations occur in this report and are easy to confuse. \textbf{(A)
Threshold-multiplier calibration}, described here, fixes a baseline multiplier $\alpha$ per CFAR
variant using \emph{noise-only} data; it concerns the CFAR statistic alone, before any comparison
with the network. \textbf{(B) Operating-point matching}, described in Section~\ref{sec:opoint}, is
the headline comparison: each detector's \emph{score threshold} is swept and the arms are compared at
the same \emph{measured} false-alarm rate. The $\Pd$ values reported in
Chapter~\ref{chp:synthetic} come from (B), not from the table below.

The multiplier achieving a chosen false-alarm rate has a closed form for CA-CFAR,
equation~\eqref{eq:alpha_ca}. It is not used. All four multipliers are instead obtained by
Monte-Carlo calibration: pure-noise frames are passed through the identical processing chain, the
CFAR ratio map is computed for each, the ratio values are pooled over all validly tested cells, and
the multiplier is taken as the $(1 - \Pfa)$ empirical quantile of that pooled distribution. The
result is the level exceeded by exactly a fraction $\Pfa$ of noise cells, by construction, and it
requires no distributional assumption --- which matters, because only CA has a tractable one.

\begin{figure}[htbp]
\centering
\includegraphics[width=\textwidth]{figures/Chapter4/ch4_fig2_alpha_calibration.png}
\caption[Threshold calibration]{Analytic multipliers do not deliver the design false-alarm rate for
any variant; calibrated ones do. Left: measured false-alarm rate against threshold multiplier on
pure-noise frames, with the calibrated value marked. Right: the rate each variant achieves at its
\emph{analytic reference} multiplier against its calibrated one, on a verification seed not used for
calibration.}
\label{fig:alphacal}
\end{figure}

The comparison multiplier in the right-hand panel is the CA expression of
equation~\eqref{eq:alpha_ca} applied with the cell count appropriate to each statistic: the full
\CfarNRef{} reference cells for CA and OS, and the half-ring count for GO and SO. That makes it
\emph{exact for CA}, a reasonable approximation for GO and SO, and for OS only a first approximation,
since an order statistic has a different distribution entirely. It is therefore labelled an
\emph{analytic reference}, not a closed-form solution per variant.

With that definition, the right-hand panel is the argument. At the analytic reference the achieved
rates are not the design rate: CA overshoots by roughly a factor of two and SO by more than six,
while OS undershoots by nearly an order of magnitude --- the largest error, as expected, for the
variant whose statistic the expression fits worst. After calibration all four sit at the design rate
on data not used to set them.

For CA, the one case where the reference is exact, the calibrated multiplier is about
\SI{10}{\percent} higher --- roughly \SI{0.4}{\deci\bel} of extra threshold.
Equation~\eqref{eq:alpha_ca} assumes the \CfarNRef{} reference cells are statistically independent,
whereas the window functions of Chapter~\ref{chp:simulator} correlate neighbouring cells, so the
effective number of independent samples is smaller and a higher multiplier is needed to hold the
rate. \textbf{This is not itself a measurement of CFAR loss}: it is a threshold difference on
noise-only data, whereas CFAR loss is a \emph{detection} penalty relative to a detector that knows
the true background power. The two are related but different quantities, and the detection penalty is
measured separately against a clairvoyant reference in Chapter~\ref{chp:synthetic}.

\section{The learned arm}

\subsection{Architecture}

The learned detector, referred to throughout as TinyCNN, is a fully convolutional network that maps a
range--Doppler map to a per-cell score at the same resolution. It has \TinyParams{} parameters.

\begin{figure}[htbp]
\centering
\includegraphics[width=\textwidth]{figures/Chapter4/ch4_fig4_network.png}
\caption[The frozen network]{Four dilated convolutional layers with the receptive field growing to
match the CFAR window. There is no downsampling, so the output remains at full range--Doppler
resolution and no peak is displaced.}
\label{fig:network}
\end{figure}

Three choices define it.

\textbf{The receptive field is matched to the CFAR window.} This is the central design decision of
the project. The layers use dilations $(\TinyDilR)$ along range and $(\TinyDilD)$ along Doppler,
composing to a receptive field of $\TinyRFR \times \TinyRFD$ --- exactly the window of
Figure~\ref{fig:window}. Dilation enlarges the receptive field without adding parameters and without
downsampling. The value was verified empirically, by back-propagating from a single output cell and
recording which input cells receive non-zero gradient, rather than trusting the arithmetic.

\textbf{There is no downsampling.} Padding equals dilation at every layer, so spatial size is
preserved exactly through the stack. Avoiding a pooling and upsampling stage removes one source of
localisation error; it does not by itself guarantee that peaks are placed correctly, which is an
empirical question addressed in Chapter~\ref{chp:synthetic}.

\textbf{The network is deliberately small.} At \TinyParams{} parameters and \TinyWidth{} channels it
is tiny by modern standards. The question is what a small learned local rule adds over a fixed one,
not how well a large network can be made to perform.

\subsection{What ``matched'' does and does not mean}
\label{sec:matched}

The receptive-field match is the fairness argument of this report, so its limits should be stated
plainly.

\textbf{Matching the footprint does not equalise the decision rule.} Both detectors see the same
$\TinyRFR \times \TinyRFD$ neighbourhood, but they use it differently. CFAR takes the cell under test
as its statistic, excludes the guard ring entirely, and estimates the background from the
\CfarNRef{} reference cells. The network has no such partition: all \CfarWinCells{} cells in its
footprint are available to it. This is a structural difference between the two decision rules, not a
difference in spatial footprint: CFAR excludes the guard cells out of necessity, because a simple
mean cannot distinguish a bright neighbour caused by a target's own mainlobe from one caused by high
noise, while a learned function is not subject to that constraint. The accurate statement is
therefore \emph{the same footprint, but CFAR is constrained to a hand-derived statistic that requires
discarding the inner cells}. Whether that difference contributes to any measured margin is tested in
Chapter~\ref{chp:attribution} rather than assumed here.

\textbf{Nominal and effective receptive fields are not the same thing.} It is a general property of
stacked convolutions that influence decays from the centre outward, whereas CFAR weights its
reference cells uniformly. The effective receptive field of this particular network was \emph{not}
measured, so this is noted as an architectural consideration rather than a measured property, and no
part of the fairness argument rests on it. The $\TinyRFR \times \TinyRFD$ figure quoted above is the
nominal receptive field, which \emph{was} measured.

\subsection{Input representation}
\label{sec:inputrep}

The input transform is a fixed part of the detector, applied identically during training and
inference: each map is expressed in decibels relative to \emph{its own frame median power},
\begin{equation}
X = \frac{1}{20}\,\mathrm{clip}\!\left(10 \log_{10}
\frac{P}{\operatorname{median}(P)},\; -10,\; +60\right),
\label{eq:norm}
\end{equation}
where $P$ is the range--Doppler power map.

The frame median is used as the reference level rather than the frame maximum, because peak
normalisation would rescale every frame by its brightest target and destroy the absolute
signal-to-noise information the detector needs. The median is a robust measure of the frame's
background scale: in the homogeneous synthetic frames of Chapter~\ref{chp:simulator} it tracks the
noise level closely, but it is a statistic of the frame, not a measurement of physical noise power,
and the two need not coincide in cluttered scenes or in real data. Chapter~\ref{chp:realdata} returns
to this, since the same fixed transform must then be applied to frames whose background statistics
differ from those it was fitted on. As noted above, this transform has no counterpart in the
classical arm, which works from power directly.

\subsection{Labels}
\label{sec:labels}

Section~\ref{sec:sota} noted that a learned detector must be given a training target and that the
choice is not neutral. The label used here is a $3\times3$ block centred on each target's cell. A
block label asks the network to respond over a small region rather than at one exact cell, which
relaxes the localisation demand relative to a single-cell label. It is retained because it belongs to
the frozen benchmark: changing it would mean the reported results no longer describe the system that
produced them. Its effect is not left open --- Chapter~\ref{chp:attribution} trains under alternative
supervision while leaving the frozen benchmark intact, so the influence of this choice on
localisation is measured rather than assumed.

Table~\ref{tab:training} gives the training configuration. Every entry is a recorded choice rather
than a default, and the whole configuration was frozen before any benchmark split was scored. It was
not revisited afterwards: the one later protocol change described in Appendix~\ref{app:prereg}
touches candidate extraction, not the network or its training.

Two entries need explanation.

\textbf{Epoch selection.} The reported epoch was not chosen by early stopping, because validation
loss plateaus later than detection probability does and would select the wrong epoch. Instead, every
epoch from 1 to 25 was evaluated on the validation split, detection probability was pooled over the
\TinySeeds{} seeds at each epoch, and the selected epoch is the \emph{earliest} whose pooled value
lies within one standard error of the plateau. The rule was written down before the sweep was
examined.

\textbf{Positive weighting.} The positive class is vastly outnumbered, and exact class balancing
would imply a weight near 974. The weight of \TinyPosWeight{} won a three-way ablation on the
validation split.

\textbf{Eight seeds are reported, always.} A single training run is one sample from a distribution,
and the spread between seeds is not negligible. Every network result in this report is a mean over
\TinySeeds{} seeds with the individual seeds shown.

\section{The evaluation protocol}

\subsection{One rulebook}

Each detector produces its own score map: CFAR works from linear power and produces a ratio map, the
network applies the normalisation of Section~\ref{sec:inputrep} and produces a logit map. Everything
after that point is shared. Both maps go through the same code, in the same order:
\begin{center}
score map $\rightarrow$ peak extraction (NMS) $\rightarrow$ operating threshold\\[2pt]
$\rightarrow$ one-to-one matching $\rightarrow$ metrics
\end{center}

\begin{figure}[htbp]
\centering
\includegraphics[width=\textwidth]{figures/Chapter4/ch4_fig5_protocol.png}
\caption[The shared evaluation protocol]{Both arms are reduced to point lists and scored through a
single code path. What differs between the two routes is the score map and the fixed
detector-specific transform that produces it; everything downstream is shared.}
\label{fig:protocol}
\end{figure}

\subsubsection*{Peak extraction}

A strong target does not produce one bright cell. It produces a small cluster of bright cells,
several of which may be local maxima. Non-maximum suppression (NMS) reduces each cluster to its
strongest cell: a cell is kept as a candidate if it is the largest value in a square neighbourhood of
side $2r + 1$, set by a suppression radius $r$. This protocol uses $r = \ProtocolNms$, a
$\ProtocolNmsWin \times \ProtocolNmsWin$ window. Candidates are extracted \emph{before} any threshold
is applied, so the candidate set is computed once and reused at every threshold the score sweep
visits.

The radius is a post-processing constant, not a property of either detector, and it was chosen on
development data only --- the tuning split for selection, the validation split for confirmation.
Neither the held-out benchmark of Chapter~\ref{chp:synthetic} nor any real data of
Chapter~\ref{chp:realdata} contributed to the choice. Radii \NmsRadiiTested{} were compared at
matched measured $\Pfa$, with the threshold re-derived at each radius so that a drifting false-alarm
rate could not confound the comparison. The outcome was simple:

\begin{quote}
\textbf{Radius 1 left duplicate in-gate detections; radii 2, 3 and 5 removed them. Radius
\ProtocolNms{} was selected as the smallest clean setting.}
\end{quote}

Two supporting measurements fix what ``clean'' means, and the full sweep is
Figure~\ref{fig:nmssel} in Appendix~\ref{app:tables}. At $r = 1$, between \NmsDupOneMin{} and
\NmsDupOneMax{} of the network's matched truths receive a second in-gate detection, and up to
\NmsDupOneCFAR{} of CA-CFAR's, against \NmsDupOther{} at every larger radius; Section~\ref{sec:matching}
explains how such duplicates can be credited to two different truths. Going the other way, a large
radius merges nearby real targets: on the masking stratum the network's $\Pd$ falls steadily from
\NmsMaskingOne{} at $r = 1$ to \NmsMaskingFive{} at $r = 5$, because a window of side
$\ProtocolNmsOriginalWin$ is far wider than the measured point-target mainlobe and removes genuine
responses from neighbouring targets. Detection itself is almost insensitive to the choice:
isolated-target $\Pd$ varies by less than \NmsIsolatedSpread{} across the whole range, for every arm.
Suppression sets how densely candidates are spaced; the threshold sets how strong they must be.

That is a statement about this evaluator on this benchmark, not a claim of a universal optimum. One
limitation remains: a $\ProtocolNmsWin \times \ProtocolNmsWin$ window is still wider than a single
point-target mainlobe, so it bounds how close two targets can be and still be reported separately.
Chapter~\ref{chp:realdata} returns to this, because real annotated objects are \emph{larger} than the
suppression window --- a regime the synthetic benchmark never exercises.

\subsubsection*{The valid region and the candidate floor}

CFAR cannot form its full $\CfarWinR \times \CfarWinD$ window near the border, so the outer margin is
excluded: $\CfarGuardR + \CfarTrainR = 10$ bins on the range axis and
$\CfarGuardD + \CfarTrainD = 4$ on Doppler. The same mask is applied to the network, so both
detectors are scored on exactly the same cells and the false-alarm denominator counts the same cells
for both.

The shared extractor also keeps only cells with a strictly positive score. CFAR scores are ratios of
powers and are always positive, so nothing is removed; network scores are logits, which are negative
wherever the predicted probability is below one half, so those cells can never become candidates.
This does not affect any reported result, since the operating points used here lie well above zero,
but it truncates the extreme high-$\Pfa$ tail of the network's ROC curve, which cannot extend below a
logit of zero.

\subsection{Matching}
\label{sec:matching}

A detection matches a truth if it lies inside the tolerance gate,
$|\Delta r| \le G_r$ and $|\Delta v| \le G_v$. Matching is one-to-one, computed by Hungarian
assignment on the distance between candidate and truth --- the pairing that minimises total distance,
with pairs outside the gate made unaffordable. A matched detection is a true positive; an unmatched
truth is a false negative.

Two consequences follow for detections landing near a real target.

\begin{itemize}
\itemsep2pt
\item \textbf{One truth gives at most one true positive.} If several detections fall inside one
isolated target's gate, exactly one is matched and the rest are ignored --- neither credited nor
charged as false alarms. Cells inside a truth's gate also leave the false-alarm denominator, so the
detector is not credited for correctly rejecting them either.
\item \textbf{Two nearby truths are different.} If their gates overlap, or one physical response
spans both, the assignment may give one peak to each truth. Several peaks from a \emph{single}
response can then be counted as \emph{two} detections. Since surplus in-gate detections cost nothing,
a detector that emits many close peaks gets extra attempts for free.
\end{itemize}

That second case is the free-attempt behaviour the suppression sweep found at $r = 1$, and it is why
the radius was not chosen on detection probability alone. The rule is applied identically to both
arms.

\centering

Two shaded regions appear in this chapter and they are easy to confuse. The \textbf{CFAR guard cells}
of Figure~\ref{fig:window} belong to the detector: they keep a target's own energy out of the
background estimate. The \textbf{near-target exclusion region} of Figure~\ref{fig:matching} belongs to
the evaluator: it decides which unmatched detections count as near misses rather than false alarms.
One is built from the CFAR window geometry, the other from the matching tolerance, and they need not
have the same extent.

\subsection{Operating point}
\label{sec:opoint}

The headline synthetic comparison is $\Pd$ at matched \emph{measured} $\Pfa$. Each detector's score
threshold is swept, the achieved false-alarm rate is measured at each setting, and the two arms are
compared where those achieved rates agree. This is stricter than matching at design $\Pfa$:
Figure~\ref{fig:alphacal} showed that achieved and design rates differ, and by different amounts for
different variants, so matching on the achieved rate removes that confound.

The sweep is performed \emph{per condition}. Each stratum gets its own sweep, and the arms are
compared at the same measured false-alarm level within that stratum. This is an \textbf{evaluation
operating point, not a deployable threshold}: it requires labels on the data being scored, and one
global setting would not achieve the same rate in every condition. Its purpose is to remove threshold
choice as a confound from the comparison.

Chapter~\ref{chp:realdata} necessarily works differently. There the network must run at a single
fixed threshold derived from synthetic validation data alone, without access to the real data it is
scored on, because real data supplies no false-alarm axis to sweep against. \textbf{Within each
experiment all detector arms share the same evaluation rule and operating-point definition; the
synthetic and real-data experiments necessarily use different operating-point protocols, and are
compared only within domain.}

\subsection{Tolerance}

The primary gate is $\pm\ProtocolGate$ bin, fixed in advance. A gate of $\pm\ProtocolGateRobust$ bins
is reported beside it as a robustness check, never instead of it. Reporting both separates detection
from localisation: a detector that finds a target but places it two bins away is credited at the wider
gate and not at the narrower one --- the detection near truth~C in Figure~\ref{fig:matching}.
Comparing the two numbers therefore shows how far a conclusion depends on localisation tolerance.
Both are reported for every condition, whichever way they point.

\subsection{Statistics}

Differences are assessed by a paired bootstrap with \ProtocolBootstrap{} resamples. \textbf{The
resampling unit is the frame.} Frames are drawn with replacement, and within each resample both arms
are re-scored on exactly the same frames, so frame difficulty cancels instead of adding noise.
Resampling whole frames also preserves the dependence among targets belonging to the same frame.
Seven conditions are scored, so significance uses a Bonferroni correction: a per-condition threshold
of $\alpha = \ProtocolBonf$ against a family-wise $0.05$.

One limitation should be noted. The operating threshold is computed once per condition and held fixed
across resamples, so the intervals capture sampling error in $\Pd$ at a fixed operating point. They
do not include the uncertainty in choosing that threshold, which would require redoing the sweep
inside every resample. The reported intervals are therefore slightly optimistic.

\section{Conclusion}

Both detectors are now fully specified, and so is the instrument that will measure them.

The classical arm uses a \CfarWinR{}\,$\times$\,\CfarWinD{} window whose guard count follows the
measured point spread function and whose shape was selected on a split reserved for that purpose,
with SO the one variant that did not take part in that selection. Its four multipliers are calibrated
on noise-only data rather than taken from an analytic expression which, as measured here, does not
deliver the design false-alarm rate for any of them.

The learned arm is a \TinyParams{}-parameter fully convolutional network whose receptive field
composes to the CFAR window. The limits of that match are set out in Section~\ref{sec:matched}: the
arms share a spatial footprint, not a decision rule, and the network is not obliged to discard the
guard cells that CFAR must exclude. Whether that difference matters is left to
Chapter~\ref{chp:attribution} to test.

The protocol reduces both arms to point lists and scores them through a single code path at matched
measured false-alarm rate, at two tolerances, with paired frame bootstrap intervals and a correction
for multiple comparisons. Its two known asymmetries --- the positive-score candidate floor, and the
fact that the operating point is an evaluation construct rather than a deployable threshold --- are
recorded above rather than left for a reader to find. The protocol was fixed, and the network
configuration frozen, before the test split was read.

Chapter~\ref{chp:synthetic} now reports what that measurement returned.
